# Described video

`/described-video` turns an uploaded file, a YouTube link or a Library video into a described copy: the original picture and soundtrack with timed spoken descriptions, as MP4 and M4A, plus a readable described transcript, WebVTT description and caption tracks and a JSON timing report. The legacy `/describe` summary feature is separate. Web and backend only.

## How a job runs

1. **Check** (free, its own worker lane so a long render never blocks it): download or import, probe, show the length and estimate.
2. **Plan** (once per job, kept in storage): one ffmpeg pass measures the soundtrack's loudness (EBU R128) and writes a small mono copy; Deepgram Nova-3 transcribes the whole film once with speaker diarization; sections of about 90 seconds break in quiet moments and snap to the picture's frame grid.
3. **Each section**: the vision model watches a 960 px copy with sound and returns a strict JSON script (people with consistent labels and names once spoken or shown, or from the first appearance for a well-known fictional character marked nameFrom known, speaker matches, timed cues with short versions and pause points, protected sounds). The next section is watched while this one is voiced. The voice gets names in their spoken form (`spokenForm` in `prompt.ts`: "Wile E. Coyote" is sent as "Wiley Coyote" and the short "Wile E." as "Wiley", and a name in the section's people ledger loses the full stop after an initial, "John F Kennedy"); the descriptions, captions and saved script keep the written names. Descriptions are voiced two at a time through the platform TTS proxy at the engine's own speed (up to 1.5×), trimmed of engine silence, and placed most important first:
   - into a dialogue gap at up to the listener's fastest speed (full text, then the short version);
   - in pause mode, starting at the pause point and freezing the picture only for what does not fit;
   - minor details (importance 1) are left out rather than pausing.
4. **Mix** in PCM: the soundtrack is brought toward -20 LUFS (at most 6 dB into the limiter), narration sits 0/2/5 dB above it (softer/balanced/louder), the soundtrack eases down 6/8/11 dB around each description and fades around pauses, then a -1 dBFS limiter. Standard mode with H.264 keeps the original picture untouched; otherwise sections are re-encoded frame-exactly so long films cannot drift.
5. **Keep**: each finished section (FLAC, picture part, JSON record) is uploaded before the next begins. A restart or redeploy puts the job back in the queue and it continues from the last finished section (three automatic tries; then a Continue button). A failed section is reported and skipped; three in a row, or an account error (HTTP 401/402/403), stops the job.
6. **Finish**: MP4, M4A, `transcript.txt`, `descriptions.vtt`, `captions.vtt`, `description.json`; phone and browser notice through the bridge (`requested: true`, like the Sound Booth). The MP4's only text track is the dialogue captions, when the film has dialogue, switched off in the file; the descriptions are already spoken, so their text is only the separate `descriptions.vtt`. Copies finished before that also carry an "Audio descriptions (text)" track: while no render is waiting, the render lane writes each one's MP4 again without it (a stream copy, free) as `described-captions.mp4` beside the original and points the copy there; the original stays until the video goes, so a link already handed out keeps working.

Re-voicing a finished copy reuses the saved script and dialogue: only speech and mixing are paid. Voice samples (`POST /sample`) are cached per voice and speed and limited to 40 an hour.

## The Kade-AI credit (Sep 27 2026)

Every described copy names the platform that described it (`credit.ts`), outside the film so it never talks over dialogue, music or the opening:

- **Before the first frame:** the sonic logo, then the job's narrator says "Audio description by Kade-AI." (about 3 to 4.5 s). Every output time moves by this lead: descriptions, dialogue and captions (`buildReport`), chapters (`outputChapters`), and the script's `outputAt` (`scriptCues(records, copy.lead)`; the copy record keeps `lead`).
- **After the last frame:** 0.6 s of breath, the logo again, then "Described by Kade-AI. More at kademurdock dot com." A preview has no closing card: its film has not ended.
- The lines are said at the engine's own speed (`min(1.5, rate)`) through `synthesize`, under the TTS session key `<session>:credit`, levelled like narration with the logo 3 LU under it and easing 4 dB down under the words. The voice proxy already says "Kade-AI" as "Kadie A I" and "kademurdock" as "Kadie Murdock". Their speech is booked through `includedMeter` (`speech-included`, charged 0).
- **Picture.** Copy mode: the original picture starts `lead` seconds later (`-itsoffset` on the picture input, an MP4 edit list) and the sound runs on past its last frame. Re-encode mode: the lead is rounded up to whole output frames and the film's first frame is held under it (`leadPicture`, the same chain and encoder as `sectionPicture`); no picture is added for the closing card.
- **Text.** `transcript.txt` has `0:00 Credit: …` and the closing Credit line at its time; `description.json` has `credit: {lead, logo, start, end}`. `descriptions.vtt` never carries the credit, so the website's next/previous-description jumps never land on it, and the description count leaves it out. Both files get the comment tag "Audio description by Kade-AI, kademurdock.com".
- **Switches.** On for every copy. `KADE_DESCRIPTION_CREDIT` = `both` (default), `end` (closing card only) or `off`. `KADE_DESCRIPTION_LOGO` = 1 to 5 (default 3) or `none`; the logos are `api/server/assets/kade-ai-logo/logo-N.flac`, passed by the wrapper as `creditLogos` (the package build copies no binary files). Only the administrator may leave the credit out of one job (`settings.credit: false`, a checkbox on the website, also on Make a new version); anyone else's request has it dropped.
- **Failure never costs the copy.** A credit whose speech or picture fails is left out and logged (`The Kade-AI opening credit was left out: …`); a logo that cannot be read leaves the words alone. `dv.claim` logs `credit`, and the engine log says `Kade-AI credit: opening 3.1 s, closing 5.1 s, logo 3.`

## Website corrections and inspection

- `GET /jobs/:id/script` returns the latest finished script, its version, and stable section/cue IDs for that version. `POST /jobs/:id/revoice` accepts `expectedVersion` and a bounded `edits` array (full text, short text, or omission). Stale versions and unknown/duplicate IDs are rejected. Original cue timing is preserved. When voice, speed, mode and volume stay the same, unaffected sections reuse their rendered media. Browser drafts are local to the job and script version.
- Finished outputs are published under `copies/<version>/` and advertised only when every output has been saved. Previous finished versions remain accessible during processing, after cancellation and after failure through `files?version=N` and `text/<kind>?version=N`. Legacy copies in the job root still work. Cancelling a new attempt does not shorten an older copy's retention.
- `POST /jobs/:id/reanalyze` writes fresh descriptions with new notes/detail/inspection settings while retaining earlier outputs. It reuses dialogue timing and soundtrack measurements. Script revisions remain tied to the latest analysis; earlier outputs can be played, but their old editable scripts are not yet separately restorable. Since Sep 27 2026 it also starts over a video whose run stopped (failed or cancelled, even one Continue refuses), from the original already kept, under a new version number; nothing is fetched or uploaded again. Each job's `describableAgain` says when it applies (a checked video that finished or stopped), and the estimate and the action refuse with a plain reason when the original is no longer in storage. After three server stops at the same part, it refuses the choices that stopped it (same part, detail, closer look and first look) unless a first-minutes preview ends before that part; the stop's own message no longer says to delete the video.
- The website (Sep 27 2026) offers Write fresh descriptions wherever `describableAgain` says so: after a finished copy (a finished preview too) and after a stopped run, beside Continue, whose detail, notes, extra passes and part then stay open for fresh descriptions only. A refusal greys the button with the estimate's reason, said once for every button it covers, never hidden and never priced at $0.00. The button's description and its confirm say nothing is downloaded (or uploaded) again and that a stopped run's finished sections are paid for again, naming Continue (or Allow more and continue) as keeping them only while it is offered. Try the preview again is reanalyze with `preview: true`, priced the same way: the `preview` action is only for a video never described, so it was refused on a finished one and the button stayed greyed. An import answer with `existing: true` opens that video and says You already have this video, and is never asked for again under a new request ID.
- Optional `closeLook` creates a 1440-pixel maximum analysis copy at quarter speed, sampling four source frames per second. Dialogue and model times use the slowed timeline; cues and protected sounds are converted back to source time before placement. Narration density/windows use original runtime. The final video's normal speed is unaffected. This improves temporal coverage but does not guarantee tiny or blurred text is readable.
- Optional `firstLook` surveys every section before narration, checkpointing each completed section in `first-look-<analysis version>.json`. The resulting people/appearance reference is separate from current narrative continuity. The prompt prohibits revealing names before they are spoken/shown, except well-known fictional characters (cartoon, puppet, mascot, game, comic) recognized on sight, which the ledger reveals from the section start; KADE_DESCRIPTION_KNOWN_CHARACTERS=off turns that exception off. This is a model instruction, not a guarantee against spoilers or misidentification. Re-voicing skips this pass.
- `GET /library-folders` suggests the owner's existing folders. Saving accepts a validated logical Library `path`, `share`, and finished `version`. The original default shelf remains the default. Concurrent saves are gated for ten minutes and deletions wait for a save to finish. Each version may be saved once.
- Extra inspection is included in estimates. New runs estimated above the configured per-run cap are rejected before provider calls. Reservation and settlement updates are serialized while paid provider requests may run concurrently.
- Opening a job restores its settings. Playback link refresh preserves position, stale file responses cannot replace another video's player, and an unsupported video cannot trigger an endless automatic refresh loop.

## Operation

- JWT auth and owner checks on every route under `/api/kade/described-video`. ADMIN only unless `KADE_DESCRIPTION_PUBLIC=1`.
- Up to 10 unfinished jobs per account; one check and one render run at a time across replicas (Mongo locks `video-check` and `video`).
- Money: starting sets aside about 1.25× the estimate from that day's allowance; a job may grow its reservation up to the per-job cap if it needs more, and unused money returns when it ends. Defaults: `KADE_DESCRIPTION_JOB_USD=5`, `KADE_DESCRIPTION_DAILY_USD=5`. Prices used: Deepgram $0.0052/min, speech $15 per million UTF-8 bytes (Fish's price; Inworld is lower), vision from OpenRouter's reported cost. With BYOK (`usage.is_byok` true, a provider key of the owner's own such as Google AI Studio) that `cost` is only OpenRouter's fee, so the provider's charge (`cost_details.upstream_inference_cost`) is added; without BYOK the upstream figure repeats `cost` and is never added (`realCost`; the same rule reads a generation record's `total_cost`, `is_byok` and `upstream_inference_cost`). A BYOK reply or record without a usable provider charge is never booked at the fee alone (which OpenRouter may waive to $0): the reply is priced like one that reported no cost, and such a record is asked for again like a missing one, then the expected cost is used.
- Balance billing (the wrapper passes a wallet): a person's run holds her approval (the estimate × 1.5 + $0.10) from her balance and, when it ends, pays what it spent, never more than the hold, and gets the rest back. Part 295 ("double everything"): the wrapper's `priceFactor` hook (`userPriceFactor`: `KADE_BILLING_MULTIPLIER`, 1 for the administrator) sets her price per real dollar. Her quotes, the `/config` per-minute prices, the job's costs and the over-quote message are at that price, the hold is her approval × the factor (`reservation.cents`, stored with `reservation.factor`), and the settlement is what was spent × the factor. Estimates, approvals, the over-quote stop and every recorded cost stay in real dollars, and `allowUpToUSD` is read at her price. Each usage row gets its real `costUSD` and `chargedUSD` (× the factor; 0 for included dialogue timing and voice samples), and a run's rows stop at its hold, as its settlement does, so a run that overran never books more than she paid. An ask cut to her balance is floored to whole cents first, so its hold (rounded up to whole cents) always fits the balance. The administrator is quoted real prices, her balance is never held (`reservation.platform`), and her rows charge 0. Runs reserved before Part 295 have no factor and settle at 1×.
- What a person is shown (Sep 27 2026): spent means settled. A paid request holds its worst-case reserve while it is out (at the `max_price` ceiling: a close look of a 75 s section about $0.38, its second look about $0.56) and settles at what it really cost ($0.01 to $0.05 a look on flex); the job counted the reserve as spent, so on her Road Runner run of Sep 27 the running cost read about 40 cents mid-run and settled near 17. Each job now sends `spentUSD` (settled only; `runCostUSD` and `costUSD`, which the iPhone 2.2 build reads, are settled only too), `heldUSD` and `heldLooks` (held right now for requests in flight, not spent; 0 once the run stops), and `costParts`: the run's settled cost by part at her price (`firstLook` learning who is who, `looks`, `closeLooks`, `secondLooks` at rushed parts, `failedTries` the provider may bill, `dialogue`, `voice`, and `other` for money a run booked before parts were kept), adding up to `spentUSD`, then work the platform paid for (dialogue timing from its own credit) marked `included`: at its real cost for the administrator, 0 for anyone else. The engine names each look's part (`Meter`'s optional fourth argument); the meter books a failed try to `failedTries`, transcription to `dialogue` and speech to `voice`. Parts are kept per run (`runParts`, `runIncluded`, `runLooks`, cleared when a run starts). The website's cost line under the progress bar (read on demand, never a live region) says, for example, "Spent so far 6 cents, of about 18 cents. The look in progress can cost at most 38 cents; you pay only what it really costs. It asks before spending more than 37 cents." (never "set aside", the page's words for the money held from a balance, which a look's worst case can pass); a finished or stopped run lists its parts in whole cents that add up to the total said (largest remainders round up: 5.6 and 11.5 cents of a 17-cent run are 6 and 11), a run from before parts were kept (only `other`) is not broken down, and the ready announcement adds the total once. The iPhone says the same words. `dv.cost` logs each finished run's total and parts on one line short enough for the server log's 150-character cut.
- A failed vision request is never booked at its worst-case reserve. The reply is streamed, so OpenRouter's generation id (the `x-generation-id` header, sent once the clip is uploaded and a provider has taken the request: 5 to 53 s in, usually about 10 s, on Sep 26) is kept even when the reply never finishes; 300 s (420 s for a second look) is a deadline for the whole request, since OpenRouter's keep-alive spaces stop axios's idle timer from firing. A failure that may be billed is priced from `GET /api/v1/generation?id=` (asked about 5, 15 and 40 s later, within a minute; `total_cost`, possibly 0, is a known charge). With no record it is booked as uncertain at the look's expected cost, at google/gemini-3.8-flash's list price on the tier that try asked ($0.375 and $1.875 per million tokens on flex, $0.75 and $3.75 on standard; the reserve stays at the `max_price` ceiling on both): about 85 prompt tokens per second of the clip as sent (a close look's clip runs four times the section) plus the prompt text at 4 characters a token, and the reasoning the look is expected to write (8,000 for a close look, about 16,000 for a second look) plus 3,000 answer tokens, never above its reserve. A standard close look of a 75 s section comes to about $0.064 against a $0.38 reserve (such looks really cost $0.048 to $0.051), a flex one to half that. A finished reply that reports no cost is priced the same way. An error sent inside a 200 reply (an `error` object with no choices, or beside a choice that finished with `error`) counts as a provider failure with its code, and may be billed whatever the code, so it is looked up too; its code 408 or 504 counts as a timeout for the one-retry rule, and its typed code (`error.metadata.error_type`) `max_tokens_exceeded` is a reply cut off at its length (one more try, as below), `content_policy_violation` or `refusal` a refusal. Requests our own stop cut off stay the platform's cost; a request that failed on its own before a stop is still priced (at its expected cost when the stop cut its lookup short). A refused request's body that stalls ends at the deadline or our stop. `dv.paid-failure` logs the provider's reason, the generation id and `settledBy` (`generation`, `reported`, `expected`, `reserve`, `unbilled`).
- How a look thinks (the Road Runner close-look A/B of Sep 26: 22 paid looks): a first-look survey at `reasoning.effort` low; a close look with `reasoning.max_tokens` 8000 in 24,000 output tokens (4,703 to 7,248 reasoning tokens and in step in 6 of 7 finished looks, $0.037 to $0.057 a look); any other look at effort medium in 12,000. A look that reasoned under 3,000 tokens (engine.ts `reasoningFloor`; the looks that ran 1.6 times slow reasoned 1,125 to 1,786) or crammed its last description at the end is looked at once more, at effort high with 48,000 output tokens and 420 s (high at 24,000 ran out of room 2 of 3 times). That second look reserves more (about $0.56 for a 75 s close look) but is weighed on real and expected cost: it, and each retry of it, starts only while her approval covers 3 times what the first look really cost (its billed failed tries included) or the second look's own expected cost when that is more (about $0.094 for a 75 s close section, where a thin first look can cost $0.019), plus the rest of the run. A reply cut off at its length is asked once more, for about half as many cues, or, when its reasoning wrote at least half of it, with the reasoning capped at a third of its output tokens (16,000 for a second look, 4,000 for a normal look; a close look's own 8,000 budget is not lowered, so it is asked for fewer cues). A second look that is cut off again, or times out twice, keeps the first look.
- Tiers (Sep 26): the same model on Google's flex tier (its lower-priority queue, half the price per token) or its standard tier. `KADE_DESCRIPTION_TIER` is `flex` (the default) or `standard`. Round 2 of the close-look bake-off (Sep 26: 25 graded looks on Road Runner, Pluto and a local news clip) found flex as good as standard (0.50 wrong details a look against 0.55, timing 0.13 s against 0.19 s, 75% of events against 73%) at about $0.020 a minute of film for the first close look against $0.037, but slower: first byte 19 to 112 s in, 72 s a look at the median, 199 s at the slowest (the deadline is 300 s).
  - Every look (survey, normal, close and second looks) on flex sends `provider: {only: ["google-vertex/global/flex"], ignore: ["google-ai-studio"], allow_fallbacks: false, max_price}` with the same `reasoning`, `max_tokens` and `json_schema` as standard. When a flex try fails in any way worth another try (busy, 429, 5xx, a timeout, an unusable or cut-off reply, or a 404 because OpenRouter has no flex endpoint), the next try, a second later, and any after it go to the standard tier with `provider: {ignore: ["google-ai-studio"], max_price}`. A flex try's deadline has 120 s more for Google's queue (420 s for a look, 540 s for a second look; `visionLimits.flexQueueMs`), and a flex timeout does not use up the one more try a timeout on standard allows, so a look that falls back keeps the two standard tries it had before the tiers. A second look (after a look that thought under the 3,000-token floor or crammed its end) asks the run's tier like any look: in the bake-off standard thought under the floor about as often as flex (3 of 11 looks against 4 of 14). Models that are not Google's are always asked on standard.
  - Once a flex try times out, or flex fails two looks in a row with no answer between (busy, rate limited, no flex endpoint), the rest of that run's looks, second looks included, ask the standard tier, and the job log says so once (engine.ts `onFlex`). In a busy spell on flex, every look would otherwise wait out its deadline or error, and may be billed for it, before standard is asked. The next run starts on its tier again.
  - Google AI Studio is left out of every look: through Kade's own key (BYOK) it bills Gemini 3.8 Flash at $1.50 and $7.50 per million tokens, and its flex was overloaded 5 of 6 tries. A `:floor` or `:nitro` suffix on `KADE_DESCRIPTION_MODEL` is dropped: `:floor` sorted her key in by price.
  - The administrator may choose a job's tier (`settings.tier`, `flex` or `standard`; the website shows the choice only to her). Anyone else's is dropped, and an unknown value is ignored. `dv.queue` and `dv.claim` log `tier` (and `tierChosen` when she picked it), every vision log line says `asked flex (google-vertex/global/flex)` or `asked standard` with the tier and provider that served it, and each section record's `vision` calls keep `requested` (the tier asked) beside `tier` (OpenRouter's `service_tier`: `flex`, or `default` for standard) and `provider`.
  - Quotes follow the run's tier. Standard: $0.021 a minute for a look, $0.025 more for a close look, $0.021 for the first look. Flex: $0.014, $0.021 more (a close look at $0.035 a minute) and $0.014. A typical flex close-look run costs about $0.029 a minute (its second looks on flex too: $0.020 for the first close looks plus 4 in 14 second looks at $0.032), and one whose every look fell back to standard about $0.055 plus dialogue timing, which her approval (1.5 × the quote + $0.10) still covers. The administrator is quoted real prices, everyone else twice them (Part 295).
- `KADE_DESCRIPTION_MODEL` (default `google/gemini-3.8-flash`), `KADE_DESCRIPTION_TIER` (`flex`), `KADE_DESCRIPTION_MAX_MINUTES` (90), `KADE_DESCRIPTION_VOICES` (parallel voice requests, default 2), `KADE_DESCRIBED_VIDEO=0` stops new work.
- YouTube: the Clubhouse jukebox's ladder (four player clients, two passes), the PO-token sidecar via `KADE_POT_URL`, optional `KADE_YT_COOKIES`; prefers H.264/AAC at 720p.
- A YouTube link she already brought in (Sep 27 2026): `POST /imports` returns the newest earlier job for the same link with `existing: true` instead of downloading it again, when that job was checked and its original is still kept, or is still being brought in; one whose import failed, or whose original is gone, is fetched afresh. An import that failed where a later try may get through (the bot wall, a climb with no settled answer, a video YouTube is still processing) is marked `checkFailure: 'transient'`, so Check again (`/recheck`) brings the link in again; a settled answer (private, removed, region, too long) is not.
- Storage: everything for a job lives under `described-video/<owner>/<job>/` (source, plan, first-look checkpoints, sections, versioned outputs) and is erased on delete or expiry (ready and stopped jobs after 3 days, or the existing finished-copy expiry if later; finished jobs after 7). A Library source is read in place and never deleted. "Save to my Library" copies the selected version's M4A to `media-library/<book>/` under the chosen logical folder.
- Gemini quirk: an integer `enum` in the response schema empties every cue object, so `importance` is a plain integer. An all-empty reply is retried once in plain JSON mode.

## Verification

Node 24 with `tsx`, `ffmpeg-static`, `ffprobe-static`, `mongodb-memory-server` and `supertest`:

```sh
node --import tsx --test packages/api/src/description/description.test.mjs packages/api/src/description/router.test.mjs
```

The media tests render real video and check audio by frequency (narration in its gap, ducking, silent pauses, frame counts across 29.97 fps sections). The router tests run whole jobs against an in-memory MongoDB and a small S3-compatible server: stop halfway, continue, re-voice, library save, notices, deletion of every stored file. Before pushing, run the package build (`tsdown` in `packages/api`), which requires explicit types on exported values.
