# Voice Changer engine — the contract (Oct 22 2026)

Kade's ask (Oct 21 2026): a voice changer in Create on the website and the
iPhone app. Not a toy with six buttons: thousands of voices and effects you
can flick through for hours, the stereo and pitch and timbre tricks of the
old voice changers and VST plugins, and the weird processing people use to
disguise voices. Record or upload speech, process it, keep it. Not an AI
voice: your own voice, changed. Fully usable with NVDA and VoiceOver, which
those plugins never were. Later: live mode, the Clubhouse, AI backgrounds.

Everything here runs on the listener's own device (browser, or a hidden
WKWebView on iPhone), so making a voice costs nobody anything.

ONE ENGINE, THREE HOSTS. The same ES-module JavaScript runs in a browser
Worker (website), in a WKWebView (iPhone), and in Node 24 (tests, listening
folders, any server render). No dependencies. No DOM, no Web Audio API inside
`core/`, `modules/`, `beds/`, `render.js` or `catalog.js`: plain math on
Float32Arrays. Hosts own decoding, playback and files.

## 1. Folder

```

  core/                     shared DSP, see section 3 (owned by the core authors)
  modules/<family>/<id>.js  one effect per file, default export (section 4)
  beds/<id>.js              one background generator per file (section 6)

  registry.js               GENERATED by tools/make_registry.js — never hand-edit
  manifest.json             GENERATED: engine version + file list
  render.js                 renderPreset / renderPreview (section 7)
  catalog.js                categories, preset loading, validation, search, combos
  host/                     worker.js, client.js (browser), bridge.js (iPhone)
  test/                     *.nodetest.mjs (node --test), helpers, fixtures
  tools/                    make_registry.js, render_cli.js, listen.js, fingerprint.js
```

Test files are `*.nodetest.mjs`, never `*.test.js` (the api's Jest would pick
those up). Run from api/server/kadeVoiceChanger with Node 24: `node --test "engine/test/*.nodetest.mjs"` (a bare folder argument fails on Node 24).

## 2. Audio buffers

```js
// A buffer is always:
{ sr: 48000, ch: [Float32Array, ...] }   // 1 or 2 channels, equal lengths
```
- Samples are nominal -1..1. Modules may exceed 1 transiently; the final
  stage limits. Modules must never emit NaN or Infinity.
- Process at the buffer's own rate (8 kHz to 96 kHz must work). A module that
  needs a particular rate (8 kHz telephone, an 8-bit console) resamples
  internally and returns at the input rate.
- A module returns a NEW buffer or mutates its input in place and returns it;
  callers treat the input as consumed.
- Mono in, mono out, unless the module's `stereo` says otherwise.

## 3. core/ — shared DSP (exact names; module authors import only these)

All functions are pure and synchronous. `sig` = Float32Array.

- `core/buf.js`: `makeBuf(sr, nch, len)`, `cloneBuf(b)`, `bufLen(b)`,
  `toMono(b)`, `toStereo(b)`, `sliceBuf(b, startSec, endSec)`,
  `padBuf(b, seconds)` (silence at the end), `mixInto(dst, src, gain=1, offset=0)` (offset in SAMPLES),
  `peak(b)`, `rms(b)`, `dbToGain(db)`, `gainToDb(g)`, `sanitize(b)` (NaN/Inf -> 0,
  returns count fixed), `fade(b, inSec, outSec)`, `mapChannels(b, fn)`.
- `core/rng.js`: `makeRng(seed)` -> `{ next() /*[0,1)*/, range(a,b), gauss(), int(n), pick(arr), fork(label) }`.
  Seeds are numbers or strings (string hashed). Same seed, same stream. Never `Math.random`.
- `core/fft.js`: `class FFT(n)` (power of two, 16..32768): `forward(re, im)`,
  `inverse(re, im)` in place, inverse scaled by 1/n. `rfft(fft, sig)` ->
  `{re, im}` of n/2+1 bins; `irfft(fft, re, im)` -> Float32Array(n).
- `core/window.js`: `hann(n)`, `sqrtHann(n)`, `hamming(n)`, `blackman(n)`, `kaiser(n, beta)`.
- `core/stft.js`: `spectralProcess(sig, { size=2048, hop=size/4, window='hann' }, (re, im, frame) => void)`
  -> Float32Array same length as sig (weighted overlap-add, unity gain when
  the callback does nothing). Also `stftFrames(sig, opts)` / `istftFrames(frames, opts, length)`.
- `core/biquad.js`: `class Biquad(type, sr, freq, q=0.707, gainDb=0)` with
  `set(type, freq, q, gainDb)`, `tick(x)`, `run(sig)` (in place), `reset()`.
  Types: lowpass highpass bandpass (constant peak) notch peak lowshelf highshelf allpass.
  `filterChain(sig, sr, [{type, freq, q, gain}...])` in place.
  `class OnePole(sr, freq, 'lp'|'hp')`. `class SVF(sr)` with
  `tick(x, freq, q)` -> `{lp, bp, hp, notch}` (TPT, safe for per-sample modulation).
- `core/delay.js`: `class DelayLine(maxSamples)`: `write(x)`, `read(delaySamples)` (fractional,
  cubic Hermite), `readLinear(d)`, `tap(d)` alias, `clear()`.
- `core/lfo.js`: `class LFO(sr, { shape='sine', rate=1, phase=0, rng })`,
  `next()` -> -1..1. Shapes: sine triangle square saw ramp random (stepped) smooth (slewed random).
- `core/env.js`: `follow(sig, sr, attackMs, releaseMs)` -> Float32Array (peak follower),
  `rmsEnv(sig, sr, windowMs)` -> Float32Array.
- `core/dyn.js`: `compress(sig, sr, { thresholdDb, ratio, attackMs, releaseMs, kneeDb=6, makeupDb=0 })` in place;
  `limitBuf(b, { ceilingDb=-1, lookaheadMs=5, releaseMs=80 })` in place, channel-linked;
  `gate(sig, sr, { thresholdDb, attackMs, releaseMs, holdMs, floorDb=-80 })` in place.
- `core/resample.js`: `resample(sig, ratio)` (output length round(len*ratio), windowed sinc,
  anti-aliased), `resampleTo(sig, fromSr, toSr)`,
  `varispeed(sig, rate, sr, opts)` where rate is a number or a function of time in seconds giving playback speed (1 = normal); always pass sr — tape stop, doppler, wow.
- `core/pitch.js`: `trackPitch(sig, sr, { minHz=60, maxHz=900, hopMs=5, threshold=0.15 })` ->
  `{ hop /*samples*/, f0: Float32Array /*Hz, 0 = unvoiced*/, conf: Float32Array }` (YIN with
  parabolic refinement and median smoothing). `f0At(track, sampleIndex)`.
  `noteOf(hz)`, `hzOf(midi)`.
- `core/voice.js` (the heart of every "voice" preset):
  `shiftVoice(sig, sr, { semitones=0, formant=0, track=null, quality='best' })` -> Float32Array same length.
  Pitch and timbre move independently. `semitones` and `formant` may be numbers or
  functions of time in seconds. Voiced speech uses pitch-synchronous overlap-add; unvoiced
  stretches use spectral envelope shifting so breath and s sounds follow the timbre.
  Must stay intelligible from -24..+24 semitones and -12..+12 formant.
  `retuneVoice(sig, sr, { targetFn /*(t, f0) => Hz or 0 to keep*/, track })` — pitch correction and monotone.
  Whole buffers (Oct 22 2026): `shiftVoiceBuf(buf, opts)` and `retuneVoiceBuf(buf, opts)` take `{ sr, ch }` with the same options and return a new buffer; one pitch analysis of the channels' mix drives every channel, so a stereo voice keeps its image (`opts.track`, if given, is a trackPitch of that mix). The target is called as `targetFn(t, f0, smoothF0)`: f0 is the cycle's own frequency (multiply it for relative changes, which keeps every cycle locked to the voice); smoothF0 is the pitch track at that moment smoothed over 12 ms, steady enough to pick notes from.
- `core/pv.js`: `stretch(sig, sr, factor)` (duration × factor, pitch kept; phase vocoder with
  phase locking, transients kept), `pvShift(sig, sr, ratio, { keepFormants=true })`.
- `core/envelope.js`: `cepstralEnvelope(mag, order)` -> Float32Array (smooth magnitude envelope),
  `lpc(frame, order)` -> `{ a: Float64Array(order+1), err }` (Levinson–Durbin),
  `lpcEnvelope(a, err, nBins)`.
- `core/conv.js`: `convolve(sig, ir)` -> Float32Array(len+irLen-1) (FFT overlap-add),
  `convolveBuf(b, irBuf, mix)` handling mono/stereo IRs.
- `core/ir.js`: `roomIR(sr, spec, rng)` -> buffer (stereo). `spec`: `{ seconds, decay /*RT60 s*/,
  predelayMs, early: [[ms, gain, pan]...] | 'auto', size /*m*/, damping /*0..1 high loss*/,
  lowCut, highCut, density, modes: [[hz, q, gainDb]...], shape: 'room'|'hall'|'plate'|'spring'|'pipe'|'box'|'outdoor' }`.
  Plus named spaces: `namedIR(name, sr, rng)` for the list in section 8.
- `core/hilbert.js`: `freqShift(sig, sr, hz)` (single-sideband, Hilbert allpass pair), `analytic(sig)`.
- `core/shape.js`: `tanh`, `softClip(x, k)`, `hardClip(x, t)`, `fold(x, t)`, `rectify(x, amt)`,
  `tube(x, bias)`, `crush(x, bits)`, `muLaw(x)`, `muLawInv(y)`, `aLaw(x)`, `aLawInv(y)`.
- `core/noise.js`: `white(n, rng)`, `pink(n, rng)`, `brown(n, rng)`, `velvet(n, sr, density, rng)`,
  `crackle(n, sr, ratePerSec, rng)`, `burstEnvelope(...)`.
- `core/segment.js`: `findPhrases(sig, sr, { minSilenceMs=180, minPhraseMs=120, floorDb })` ->
  `[{ start, end }]` in samples (speech stretches between pauses), `findSyllables(sig, sr)`.
- `core/space3d.js`: `place(mono, sr, path)` -> `{ L, R }` where `path(t)` returns
  `{ az /*deg, 0 front, +90 right, ±180 behind*/, el /*deg*/, dist /*m*/ }`. Spherical-head model:
  interaural time and level difference, head shadow, pinna notch for elevation and the
  front/back cue, distance gain and air absorption, doppler when dist changes.
- `core/automate.js`: `curve(spec, len, sr)` -> Float32Array. `spec` is a number, `{from, to, shape:'lin'|'exp'|'sine'}`,
  or `[[tSec, value], ...]`. `at(spec, tSec, durSec)` for a single value.
- `core/loudness.js`: `lufs(b)` (BS.1770 K-weighted, gated), `normalizeLufs(b, target=-16)` in place,
  `truePeakDb(b)` (4× oversampled).
- `core/wav.js`: `encodeWav(b, bits=16)` -> Uint8Array, `decodeWav(u8)` -> buffer (PCM 8/16/24/32 int, 32/64 float).
- `core/params.js`: `resolveParams(module, p)` -> full object with defaults, numbers clamped and
  snapped to step, choices validated; `speakValue(param, v)` -> plain words
  ("up 3 semitones", "250 milliseconds", "40 percent", "minus 6 decibels", "1.5 times", "off").

## 4. A module (an effect)

One file, `modules/<family>/<id-after-dot>.js`, default export:

```js
export default {
  id: 'pitch.voice',          // family.name — STABLE FOREVER (presets and saved chains point at it)
  name: 'Pitch and timbre',   // short spoken name
  family: 'pitch',
  about: 'Moves your voice up or down. Timbre makes the person sound bigger or smaller.',
  params: [
    { id: 'semitones', name: 'Pitch', type: 'number', min: -24, max: 24, step: 0.5, def: 0, unit: 'semitones' },
    { id: 'formant', name: 'Timbre', type: 'number', min: -12, max: 12, step: 0.5, def: 0, unit: 'semitones' },
    { id: 'mode', name: 'Method', type: 'choice', def: 'auto',
      options: [{ v: 'auto', name: 'Automatic' }, { v: 'smooth', name: 'Smooth' }] },
    { id: 'keepBreath', name: 'Keep breath', type: 'bool', def: true },
  ],
  stereo: 'keep',             // 'keep' (same channel count out), 'make' (always stereo out), 'mono' (always mono out)
  tail: (p, sr) => 0,         // seconds of sound added after the input ends (echo, reverb)
  warps: false,               // true when output timing no longer lines up with the input
                              // (tempo, reverse, stutter, trim, shuffle): the Effect strength
                              // macro then cannot blend dry and wet and is skipped for the chain
  cost: 2,                    // rough CPU weight 1..5 (5 = phase vocoder heavy)
  process(input, p, ctx) {    // p is already resolved (defaults filled, clamped)
    // ctx: { sr, rng /*seeded per stage*/, progress(fraction), cancelled() }
    return input
  },
}
```

The other sound (side input, Kade's ask Oct 22 2026: "mixing voice with other signals"):
- A module that can use a second sound sets `side: true` and offers the choice value `side`
  (spoken "The other sound") in its carrier/source param. In `process`, `ctx.side` is that sound as
  a buffer at the take's rate, already looped (equal-power crossfade) or trimmed to the input length,
  or `null` when the host gave none — then the module falls back to its first built-in carrier and
  says so through `ctx.note('...')` (render.js collects notes into the report).
- The other sound comes from the person (a second recording or file: "My own sound") or from the
  platform's recorded sound library (a sound-file bed id). A preset may name one with a top-level
  `"side": "<sound-file bed id>"`; the person's own choice overrides it. Hosts supply it as
  `opts.sideAudio` (decoded buffer); the Worker and iPhone bridge keep it under the id `side`.

Rules:
- A number param may carry `rand: [lo, hi]`, the range "Surprise me" draws from when it builds a
  brand-new random chain (pick ranges that always sound good; omit to use min..max). A module may
  set `surprise: false` to stay out of random chains (cleanup tools, extreme effects).
- Units: `semitones cents percent ms seconds hz db x bits degrees meters bpm count steps`.
  Percent params run 0..100 (or -100..100). `mix` (dry/wet) is percent 0..100 when present.
- Every param has a plain spoken `name`; choices have spoken names. No jargon in names
  where a plain word exists ("Echo time", not "Delay ms").
- No person names, no trademarks or brand names in any `name`, `about` or choice name.
- Deterministic: randomness only from `ctx.rng`.
- Stereo-in must work for every module (process channels independently or mid/side).
- `process` must handle: 0-length input, pure silence, a single click, 30 s of speech,
  every param at min, def and max — no NaN, no Infinity, no exceptions, peak under 8.
- Speed target in Node: cost 1–2 under 20 ms per second of 48 kHz mono; cost 5 under 400 ms.
- Optional `live` (realtime: the website's live mode now, the Clubhouse disguise and an iPhone port later):
  ```js
  live: {
    latency(p, sr) { return 0 },            // samples of delay this stage adds to the dry path
    create(sr, p, rng) {                     // called off the audio thread; allocate everything here
      return {
        process(ins, outs, n) {},            // ins/outs: arrays of 1 or 2 Float32Array views, n = 128 (worklet) or 480 (10 ms WebRTC) or any size
        set(p) {},                           // new resolved params; must not allocate; smooth jumps (no zipper clicks)
        reset() {},
      }
    },
  }
  ```
  `process` may be called with `outs` aliasing `ins`. No allocation, no closures created, no
  exceptions inside `process`. Mono in with stereo out is allowed for `stereo: 'make'` modules.
  A live version should sound like the offline one; it may be simpler (an algorithmic reverb in
  place of a long convolution) but must never change the offline output.
  Live chains are presets whose every stage has `live`; `catalog.js` marks them `live: true`.

## 5. A preset

```json
{
  "id": "giant-in-a-cave",
  "name": "Giant in a cave",
  "cat": "creatures",
  "sub": "Giants and ogres",
  "about": "A huge slow voice booming off wet stone.",
  "tags": ["deep", "huge", "echo"],
  "chain": [
    { "m": "pitch.voice", "p": { "semitones": -8, "formant": -6 } },
    { "m": "space.room", "p": { "space": "cave", "mix": 40 } }
  ],
  "bed": { "b": "cave", "level": -26, "p": {} },
  "seed": 1
}
```
- `id`: lowercase words joined by hyphens, unique across ALL categories, STABLE FOREVER
  (favorites, recents and saved creations store it). Rename by changing `name` only.
- `name`: 2–6 plain words, unique within its category, says what you will hear. No person
  names, characters, brands, trademarks, or slurs. ("Tin invader", not a TV robot's name.
  "Pitch correction, hard", not a product name. "Rotating speaker", not a brand.)
- `about`: one spoken sentence, under 120 characters.
- `chain`: 1–8 stages; `p` lists only params that differ from the module default.
- `bed`: optional background (section 6), `level` in dB relative to the voice's loudness.
- Category ids and spoken names are fixed in `catalog.js` (section 9).

## 6. A background bed

`beds/<id>.js`, default export:
```js
export default {
  id: 'rain',                 // STABLE FOREVER
  name: 'Rain',
  group: 'weather',
  about: 'Steady rain, close enough to hear drops.',
  params: [ /* same param shape as modules, e.g. intensity, surface: window|roof|tent|leaves */ ],
  generate(seconds, sr, p, rng) { return { sr, ch: [L, R] } },  // stereo, exactly `seconds` long
}
```
Beds are made from synthesis (noise, filters, grains, modal resonators, event
scheduling), never from bundled recordings, so they are ours to ship. Each must
sound like the real thing to an ear, not like filtered noise. Loop-free: they are
generated to the exact length needed, with natural variation (gusts, distant
events) driven by `rng`. `render.js` mixes them: level, fade in and out, optional
ducking under the voice.

## 7. Rendering

`render.js`:
- `renderPreset(input, preset, opts)` -> `{ buf, report }`.
  `opts`: `{ macros: { pitch=0, timbre=0, speed=1, amount=100, bed: {b, level, p} | null | undefined,
  width=100, volume=0 }, cleanup=true, loudness=-16 | null, seed, progress, cancelled }`.
  Steps: sanitize -> optional cleanup (DC, 70 Hz high pass) -> macros (pitch/timbre add to the
  first `pitch.voice` stage, or insert one first; speed is tape-free tempo via `core/pv.stretch`)
  -> each chain stage (seeded rng per stage, progress shared) -> `amount` blends wet with the
  aligned dry signal -> bed mixed under -> stereo width -> loudness normalise -> limiter at -1 dBTP.
  `report`: `{ ms, stages: [{ m, ms }], peakDb, lufs, fixedNaN }`.
- Sound-file backgrounds: besides synthesized beds, a bed may be a decoded sound file the host
  supplies (the platform's own AI-made ambience loops, and later a person's own generated ones):
  `bed: { file: '<id>', level, duck, fade }` with `opts.bedAudio` = the decoded buffer. render.js
  resamples it to the take's rate, loops it with an equal-power crossfade (0.6 s) when shorter than
  the take, starts at a seeded random offset, and mixes it exactly like a synthesized bed.
- `renderPreview(input, preset, opts)` — same, on `opts.start`..`opts.start+opts.seconds` (default 0..6).
- `renderChain(input, chain, ctx)` for custom racks.
- Unknown module ids or bad params throw `VCError` with a plain sentence.

## 10. Hosts

- The server serves this folder read-only at `/vc-engine/<version>/` (immutable cache, CORS *),
  where `<version>` is `manifest.json`'s version. Every relative import then resolves inside one
  version, so no `?v=` is needed anywhere. Generated `catalog.json` (the browsable index: categories,
  presets id/name/cat/sub/about/tags/live, beds list), `modules.json` (every module's id, name,
  family, about, params, live flag) and `beds.json` sit next to `manifest.json`.
- Website `/voice-changer`: a module Worker (`host/worker.js`) holds the loaded take and renders;
  `host/client.js` is the page-side API (load, preview, render, cancel, getPreset). The page owns
  recording (MediaRecorder, echo cancellation and noise suppression OFF), decoding
  (decodeAudioData), playback (one AudioContext) and saving. Previews render 6 s by default.
- iPhone: a hidden 1x1 WKWebView (kept in the window, like the Clubhouse engine) loads
  `https://kademurdock.com/voice-changer/engine` (served no-store), which imports `host/bridge.js`
  from `/vc-engine/<version>/`. The page is pure compute: no AudioContext, no microphone. Native
  sends the take as 16-bit WAV in base64 chunks (`vcBridge.feed(id, seq, b64, last)`), asks for
  previews and full renders (`vcBridge.render(json)`), and receives WAV results as base64 slices
  over `webkit.messageHandlers.vc` (`{t:'chunk', req, seq, b64}`, `{t:'done', req, report}`,
  `{t:'progress', req, f}`, `{t:'error', req, message}`, `{t:'ready', version}`). Native decodes,
  plays (AVAudioPlayer), encodes and owns every control, so VoiceOver is fully native.
- A sound the engine cannot read or keep is answered with `{t:'error', req, id, message, code}`
  carrying that sound's id (req is null for `feed`), and `feed` returns false for it, so a native
  waiter for that id always resumes.
- Node: `tools/render_cli.js in.wav preset-id out.wav` and `tools/listen.js` for listening folders.
